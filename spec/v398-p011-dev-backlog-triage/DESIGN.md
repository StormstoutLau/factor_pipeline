## 3. 架构设计

### 3.1 产出物拓扑

```
RESEARCH.md（证据与裁决依据）
      │  D1 裁决矩阵
      ▼
DEV_PROGRESS.md §4（冻结历史 + 逐行裁决，只读）
PROGRESS.md（待办真值源：P-011 状态 / P-018 立项）
PROJECT_STATUS.md（仅指针：流式 → P-018；AR 关闭；内生性 → P-009）
      │  D2/D5
      ▼
下游批次：P-018（T2，含 U-4~U-6）、P-009（待开 Step 1）
```

### 3.2 模块划分（文档职责）

| 模块 | 职责 | 输入 | 输出 | 依赖 |
|---|---|---|---|---|
| 裁决矩阵 | 11 条的现状 / 裁决 / 置信度 / 证据 | RESEARCH §3 | DEV_PROGRESS §4 三列 | E1 锚点 |
| 真值源 | 唯一待办状态出口 | 裁决矩阵 | PROGRESS 行 | D5 |
| 指针层 | 只加注记、不复制裁决 | PROGRESS 去向 | PROJECT_STATUS 两行 + T2 节 | D5 |
| 触发条件登记 | 可机械识别的重开条件 | RESEARCH §3.3/§3.5 | DEV_PROGRESS 行内文本 | D3/D4 |
| 复审记录 | 双视角审查与处置 | 全文档 | RESEARCH §8 | D8 |

### 3.3 数据流

`裁决 → 行级回填 → 真值源 → 指针 → 下游批次`。任何一步**不得反向改写**上游：PROJECT_STATUS 不定义裁决，DEV_PROGRESS §4 不再更新，只有 PROGRESS 承接状态变化。

### 3.4 控制流

1. 判定 Layer-0（改动路径 ∩ 门禁路径 = ∅）→ T3。
2. 执行 D1 裁决表回填。**（现状注记，复审 A-4：步骤 2-3 已在 Step 1-2 期间执行完毕，RESEARCH §6.4/§8.2 有记录；本节仅作方案描述，执行者不得重复回填。）**
3. 执行 D5 三账本同步（最小集）。
4. 执行 D8 复审；未闭合项进 U 四元块。
5. 提交边界：仅 `docs/` 三账本 + `spec/v398-p011-dev-backlog-triage/`，不触碰代码与门禁。

## 5. 替代方案

### 5.1 方案 A：文档级裁决 + 三账本指针（选择）

- 描述：11 条逐行裁决，PROGRESS 为真值源，PROJECT_STATUS 仅指针。
- 优点：零代码风险；历史可追溯；下游可直接接续。
- 缺点：保留 DEV_PROGRESS 冻结表，账本体积不减。
- 选择理由：与 T3 档位、验收标准 ① ②（出处：[PROGRESS.md](../../docs/PROGRESS.md#L30) P-011 行，复审 A-3 补指针）完全对齐。

### 5.2 方案 B：删除 DEV_PROGRESS §4（否决）

- 优点：账本最简。
- 否决理由：丢失历史原文与审计线索；违反「冻结备查」原则；无法回查第 1/2/3 条的原始诉求。

### 5.3 方案 C：升级 T1，在 P-011 内实施流式 / 删类（否决）

- 优点：一次做完。
- 否决理由：~1500+ 行、8+ 文件，且删类违反 PEP 387 / SemVer（O2/O3）；与「零生产改动」硬约束冲突。

### 5.4 方案 D：T3 也写完整四文档（否决）

- 优点：形式统一。
- 否决理由：SPEC_PROCESS 明确 T3 不强制四文档；IMPLEMENTATION/CHECKLIST 对零代码批次无验收对象，属过度工程。

### 5.5 方案 E：只改 RESEARCH，不动账本（否决）

- 优点：改动最小。
- 否决理由：P-011 验收 ② 要求「裁决结果回填 PROGRESS，DEV_PROGRESS 不再承载待办」；不满足即未验收。
