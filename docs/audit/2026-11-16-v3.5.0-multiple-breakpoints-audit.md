## Phase 6 — 自审

| 质疑 | 回应 |
|------|------|
| 为什么 Stata 侧不用 Mata 写 DP? | 官方 `regress` 的 `e(rss)` 独立性更强 (官方数值库); Mata 重写只能证明「转写无误」, 不能锚定公式。m≤2 的穷举耗时仅 ~3s |
| 为什么 m≥3 不对拍 Stata? | m=3 的组合数在 T=120 时约 3 万, 循环 `regress` 需 ~2 分钟且收益递减; m≥3 的 DP 正确性由 Python 内部穷举 (E5) 保证, 且 DP 递推与 m=2 同构 |
| BIC 短样本偏高估怎么办? | ①同时报 LWZ (更保守); ②不接入 `diagnose` 标签; ③E7 用 `m_max=1` 隔离索引映射测试; ④ADR 后果显式记录 |
| 为什么不硬编码 Bai-Perron 临界值? | 无可靠表副本; 硬编码 = 编造风险。BIC/LWZ 选段数是 Bai-Perron (2003) 的正规替代 |
| 真实数据「检出 2 断点」是否可信? | **复审已推翻**: BIC_0=-8.207 < BIC_1 < BIC_2, 均选 m=0 (无断点); [19,37] 是强制 m=2 的最优位置。初版文档误读, 已全量更正 (D10) |
| `ssr_mat` 稠密矩阵是否浪费? | T=200 时 201²×8B ≈ 323KB, 可忽略; 仅当 T>2000 才需优化 |
| 是否可能与 `detect` 结论冲突? | 是可能的 (单断点网格 vs 多断点全局): E8 已断言 m=1 断点差 ≤1 且 DP 的 SSR 不劣于网格; 冲突时以多断点为准, 但 `diagnose` 仍用单断点 (契约隔离) |

## Phase 7 — 审计结论

**PASS**。6 个实施期缺陷 (D1 解析正则 / D2-D3 判据 / D4-D5 测试自身 /
D11 `m_max` 契约) 全部在交付前修复; 2 项设计取舍 (D7 不做临界值判定 / D8 稠密矩阵)
已在 ADR/审计显式记录。全量回归 1768 passed / 15 skipped / 0 failed (无新增失败)。

**核心验证**: Stata 官方 `regress` 对拍 **46/46 PASS** —
断点集逐点相同、SSR 相对误差 ≤8.5e-9、BIC/LWZ 绝对误差 ≤8.5e-9、单断点 F 相对误差 1.06e-8。
多断点公式与主控站 Stata 一致性的要求已满足。

**局限**: ①未对 m≥3 做 Stata 对拍 (由内部穷举补足); ②BIC 短样本假阳性偏高
(复审 H6: 44% T=72 / 36% T=120; LWZ 更高 89%/75% → H5 降级为仅对照) + 不接入标签;
③真实数据 BIC/LWZ 判 m=0 无断点 (初版「检出 2 断点」为文档误读, 见 Phase 8 H4)。
