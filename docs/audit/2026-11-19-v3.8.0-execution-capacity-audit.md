## Phase 3 — H2 真实缺陷与修复（P2 级，唯一）

**机理**：[classification.py](../../backtest/execution/core/classification.py) 的 `detect_limit_lock`
frozen 分支实现为 `(v==0) & (o==c) & (c==h)`，漏掉 `c==l`；EXECUTION §2.7 spec 为
「**开=收=高=低 且 volume==0**」。`v==0` 但 `o=c=h`、`l<h` 的异常 bar（脏数据形态）会被误判为一字板，
进入 `MinuteAggregate.limit_lock` 聚合（lock 求和 → 股票日级 `limit_lock = lock/n >= 0.5`）。

**红证据**（首轮 P5-5k，修复前）：合成异常 bar `h=10, l=9.5, c=10, o=10, v=0` → 修复前返回
True，spec 应 False；正常 `o=c=h=l=10, v=0` bar 必须仍命中。

**修复口径**：frozen 分支补 `& (c == l)`，一行变更：

```python
flat = (h == l)
frozen = (v == 0.0) & (o == c) & (c == h) & (c == l)
return np.asarray(flat | frozen, dtype=bool)
```

**回归测试**（1 例）：`test_limit_lock_zero_volume_requires_low_equal`（T380-25b，
[test_execution_classification.py](../../tests/test_execution_classification.py)）——
断言异常 bar 修复后 False、正常 o=c=h=l bar 仍 True。

**真实数据零影响核验**（探针 P5-5k 附加，2026-11-19 实跑）：2023-03-01 单日 908,088 bar 逐 bar 对比
frozen_old（缺 `c==l`）vs frozen_new（含 `c==l`）——**frozen_old = frozen_new = 168,391 bar，
差 = 0**。真实数据中不存在 `v==0 且 o=c=h 但 l<h` 的 bar → 判定集合逐位一致 →
CHECKLIST E1 各级占比（含一字板占比 6.69%、零成交 bar 3.75%）**不变**；
默认路径 golden（SHA256 `82728CE1…`）不受影响（57 例含 `test_execution_default_snapshot` 通过）。
零新增依赖；`backtest/__init__.py` / `backtest/data_contract.py` 零改动。
