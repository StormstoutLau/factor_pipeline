## §1 目的

ADR-042 的工程证据此前只有两层: 单元级逐位等价 (T2/T3, 合成数据) 与性能门禁 (ratio 1.0092)。本实证补第三层——**真实数据上回答三个问题**:

1. v3.3.7 的「指纹标签 → 执行管道」是否真的一致?
2. 改为统一管道后, 因子截面信号 (秩/IC) 是否保持?
3. 被移出默认路径的 Dynamic 臂, 作为反事实其代价与收益如何?

## §3 执行路由实测 (关键发现)

| 因子 | v3.3.7 诊断标签 | v3.3.7 **实际执行管道** | v3.4.0 执行管道 |
|------|----------------|------------------------|----------------|
| `LT_debt_ratio` | static (0.869, secondary mixed 0.128) | **MixedFactorPipeline** | Static (unified) |
| `UTR_turnover` | unknown (0.0) | **DynamicFactorPipeline** | Static (unified) |

机制: v3.3.7 `fit` 在指纹分类之后还有一步 `StatisticalClassifier(alpha=0.05, vr_q=5)` 覆写 `pipe_type` ([pipelines_v2.py L1372-1378](file:///F:/Coding/fp_baseline_ab/pipelines_v2.py#L1372-L1378)), 但写入 `factor_classifications` 的仍是上一步的指纹标签。结果是**诊断标签与执行管道 2/2 错位**。

这为调研结论「指纹与 VR/DF 标签一致率 49.5%」提供了直接代码路径证据: 两个分类器串联, 执行由后者决定, 而对外可见的标签来自前者。v3.4.0 删除该串联后, 标签 (只读诊断) 与执行 (unified/static) 不再互相冒充。

## §4 输出一致性与分布

| 因子 | 对比 | 逐期秩相关 ρ (mean / min) | ρ≥0.999 期数占比 | mean\|Δz\| | max\|Δz\| | 精确相等 |
|------|------|--------------------------|------------------|-----------|-----------|---------|
| LT | base vs cur | 0.9999990 / 0.9999990 | 100% | 0.0083 | 1.104 | 否 |
| UTR | base vs cur | 0.9999990 / 0.9999990 | 100% | 0.2469 | 1.196 | 否 |

**分布尾部**:

| 因子 / 版本 | \|z\|>2.5 占比 | \|z\|>3 占比 | 说明 |
|-------------|---------------|-------------|------|
| LT / base (Mixed) | 1.25% | 0.25% | Mixed 3σ 缩尾, 尾部保留至 3σ 外 |
| LT / cur (Static) | 2.00% | 0% | 1%/99% 缩尾 + rank→normal, 尾部被截断 |
| UTR / base (Dynamic) | 0% | 0% | 12 期下 AR 解耦退化, 输出无厚尾 |
| UTR / cur (Static) | 2.01% | 0% | 同上: 1%/99% 截断 |

结论: 两版本在**排序层面等价** (ρ≥0.999999), 差异集中在尾部处理 (Mixed 3σ vs Static 1%/99%) 与月频 Dynamic 的退化行为。ADR 中「原 static/mixed 因子输出逐位不变」在真实数据上不成立——因为基线实际执行的是 Mixed 而非标签所示的 static; 正确表述应为「**秩等价、尾部口径不同**」。

## §6 Dynamic 反事实 (v3.4.0 `pipeline_mode='dynamic_ab'`)

| 因子 | cur vs cur_dyn 秩相关 | IC (unified / dynamic) | ΔIC NW t | LS 年化 IR (unified / dynamic) | fit+transform 耗时 |
|------|----------------------|-----------------------|----------|-------------------------------|-------------------|
| LT | **0.140** | −0.00317 / −0.00118 | −0.34 | −1.87 / +1.17 | 172.05s vs 5.96s |
| UTR | 0.999999 | −0.07044 / −0.07044 | −0.18 | −0.07 / +0.07 | (同上, 同批运行) |

- LT (AR(1) 中位数 0.989): Dynamic 显著改变截面排序 (ρ=0.14), 但 IC 与多空收益均无统计显著改善 (t=−0.34; LS t≈1.03), 耗时约 **29×**。
- UTR (12 期): Dynamic 在短面板上退化为单调变换, 秩与 Static 完全一致 (ρ=0.999999), 即该臂在此数据上不可辨识。

这支持 ADR-042 决策 6: Dynamic 仅作整臂显式实验保留, 不参与默认路由。

## §8 局限

1. **样本**: 2 个因子、2023 单年; 月频仅 11 个前瞻收益观测, 统计功效有限。
2. **价格不复权** (`adjust=none`): 前瞻收益含除权除息噪声。
3. **无行业/市值数据**: 中性化被跳过; 两版本一致, 不影响版本对比, 但结论不能外推到启用中性化的场景。
4. **股票池未做停牌/涨跌停/ST 过滤**: 多空收益为理论值。
5. **基线标签来源**: `get_classification_summary()` 记录的是指纹分类, 执行管道由 `StatisticalClassifier` 覆写; 本报告以 `factor_pipelines` 实际键为准。
6. 单年结论不能替代多年/多市场稳健性检验 (建议后续用 `AblationRunner` 扩样本)。

## §9 结论与建议

1. **路由标签-执行错位是真实缺陷**: 基线 2/2 因子的诊断标签与实际管道不一致 (static→Mixed, unknown→Dynamic), v3.4.0 统一后消除。这是本次治理最硬的真实数据证据。
2. **统一管道保持秩层面信号**: 两因子 ρ≥0.999999, ΔIC 的 NW t 分别为 0.54 / 0.18, 无统计差异; 差异仅在尾部口径 (1%/99% vs 3σ)。
3. **Dynamic 默认退场合理**: 反事实臂在日频因子改变排序 (ρ=0.14) 却无 IC 改善, 代价 29×; 在月频短面板退化不可辨识。
4. **性能**: 统一管道较基线快约 1.8×。
5. **建议后续**:
   - 用 `AblationRunner.run_l2` 扩到多年/多因子 (至少 10 个因子、3 年以上), 输出统一报告;
   - 若未来启用行业/市值中性化, 需重跑本 A/B (中性化可能放大管道差异);
   - 将本报告的 ρ/ΔIC 统计纳入发版检查项 (真实数据 A/B 作为 regressions 的补充)。

## §10 复现

1. 基线环境: `git worktree add <OUT> 0ff2420`, 建 junction 使包名为 `factor_pipeline`, `sys.path` 指向 junction 父目录。
2. 数据: 直接 `pd.read_parquet('cache/*.parquet')`; 因子矩阵转置为 `dates × stocks`。
3. 运行: 每版本独立进程, 设置 `AB_PKG_ROOT` / `AB_OUT` / `AB_LABEL` / `AB_MODE` (default / unified / dynamic_ab), 执行 `fit` → `transform`, 保存输出面板。
4. 对比: 逐期 Spearman IC、ICIR、NW t、多空 IR、逐期输出秩相关与 tail 占比。
5. 探针脚本位于本次会话临时目录 (`%TEMP%/ab_run.py`, `ab_compare.py`), 未入库; 如需长期保留可迁入 `scripts/`。
