## §2 D1 执行时点：`same_close` vs `next_open`

### 2.1 现状事实

| 事实 | 锚点 |
|---|---|
| `TradabilityPolicy.execute_at` 默认 `"next_open"`，但仅做合法性校验，循环体内从未读取 | [tradability.py L316-L318](../../backtest/tradability.py#L316-L318) |
| 判定使用 **T 日** `high/low`：`can_buy = ~(high >= up)`、`can_sell = ~(low <= down)` | [tradability.py L385-L386](../../backtest/tradability.py#L385-L386) |
| `open_` / `volume` 只做形状校验，未参与任何判定 | [tradability.py L330-L335](../../backtest/tradability.py#L330-L335) |
| 前向收益是 **close-to-close**：`fwd_ret[t] = close[t+1]/close[t] - 1` | [engine.py L173](../../backtest/engine.py#L173) |
| 仓库设计原文：C9「买入在信号确认后的下一根 bar」；C10「执行价整体前移一根 bar 重跑」 | [RESEARCH_SYNTHETIC_VALIDATION_TRACEABILITY.md L500](RESEARCH_SYNTHETIC_VALIDATION_TRACEABILITY.md#L500)、[L253](RESEARCH_SYNTHETIC_VALIDATION_TRACEABILITY.md#L253) |

结论：当前实现是「用 T 日 high/low 判定 T 日目标权重」，既不等于 `same_close`（收盘价触板），也不等于 `next_open`（次日开盘触板），是第三种未命名的口径。

### 2.2 量化：三种口径的封锁池（E1）

样本 1394 日 × 5688 只；限价按板块名义档位；只统计「该方向不可成交」的格（买：价格 ≥ 涨停价；卖：价格 ≤ 跌停价）。

| 口径 | 买入封锁格 | 相对现状 | 卖出封锁格 | 相对现状 |
|---|---:|---:|---:|---:|
| **touch（现状：T 日 high/low 触及）** | **127,937** | 100% | **43,613** | 100% |
| **same_close（T 日收盘价触板）** | **86,039** | 67.3% | **24,694** | 56.6% |
| **next_open（T+1 开盘价触板）** | **17,373** | **13.6%** | **11,591** | **26.6%** |

分板块（买入 / 卖出）：

| 板块 | touch | same_close | next_open |
|---|---:|---:|---:|
| 主板 | 113,530 / 41,134 | 76,082 / 23,329 | 15,903 / 10,932 |
| 创业板+科创板 | 13,214 / 2,243 | 9,099 / 1,206 | 1,200 / 549 |
| 北交所 | 1,193 / 236 | 858 / 159 | 270 / 110 |

- 句子级结论：换口径不是「小幅修正」，而是把封锁池缩小 **1.5-7 倍**（买入 1.5-7.4×、卖出 1.8-3.8×）；`turnover` 的启用前后差异会被口径选择完全主导。
- **口径脚注**：本文「touch」用引擎谓词 `high >= limit - eps`；未决项文档的 115,923 用精确相等 `|high - limit| <= eps`，是本文的子集（127,937）。两者差 12,014 格，主要来自 high 略超限价的数据噪声；结论方向不变。
- **样本脚注**：本节 127,937 / 86,039 / 17,373 均基于 1394 日（`adj` ∩ OHLC），不含 81 个 `adj` 缺口日；缺口日的 403,499 格另见 §3。两组数不可相加。
- 限价按板块名义档位（ST 5%、创业板 2020-08-24 前 10% 未细分）→ 触板池为**下限**，与未决项文档 §2.2 的口径局限一致。
- 反向漏封（当前放行、新口径应封锁）：`next_open` 方向 7,116 买 / 8,253 卖（占全部可交易格 0.10%-0.12%）；`same_close` 方向为 0（收盘价触板必然是 high 触板，属 touch 的子集）。
- 口径局限：这是**报价可行性池**，未乘真实调仓 delta；真实影响需在 B 批用因子权重测量（V-2）。

### 2.3 外部锚点

| 来源 | 结论 | 等级 |

| [Qlib 文档（Workflow/Estimator）](https://qlib.readthedocs.io/en/stable/component/workflow.html) | `deal_price: close` 是默认值；即「当前 bar 收盘价成交」 | ✅ 原文配置片段 |

| 仓库 C9/C10 | 设计不变量要求「信号确认后的下一根 bar」执行，并用 one-bar ablation 检验同 bar 前视 | E2（仓库设计原文） |
| A-4（T+1 隔夜折价，JBF 2020） | 隔夜段存在系统性收益折价，close-to-close 与 open-to-close 不可混用 | ⚠️ 摘要级 |

### 2.4 选项对比

| 选项 | 做法 | 优点 | 代价/风险 | 适用条件 |
|---|---|---|---|---|
| A `same_close` 改名 | 删除 `next_open`；把判定改为 `close >= up` / `close <= down` | 与 Qlib 默认一致；改动小；无需 shift | 若因子使用 T 日收盘数据，则构成同 bar 前视；与仓库 C9/C10 冲突 | 必须逐因子证明「T 日收盘前可得」；否则不可用 |
| **B 实现 `next_open`（推荐）** | 目标权重后移 1 日；判定用 `open[t+1]`；报告 `execution_timing="t_plus_1_open"` | 与仓库 C9/C10 一致；无同 bar 前视；`open_` 终于被消费 | 需处理首日/末日、T+1 停牌/无报价；turnover 序列整体后移 1 日；IC 仍是 close-to-close（R-4 已披露） | 默认推荐 |
| C 保留现状 + 披露 | 只加 `execution_timing="t_day_touch"` | 零改动 | 字段名与语义仍不一致；无法通过 one-bar ablation | 仅作过渡 |

### 2.5 推荐与「什么会改变推荐」

- **推荐 B**：仓库设计原文已经选了 next-bar；`open_` 已在输入里；Qlib 的 close 默认不构成反证，因为 Qlib 的因子/标签口径自成体系，而本仓的 C9/C10 是已冻结的设计不变量。
- 若选择 A，必须先做**因子时点审计**：对每个因子标注「数据截止日」，证明所有输入在 T 日收盘前可得；否则 A 是前视，不能用于证据层。
- 无论 A/B，都必须删除「T 日 high/low」这一混合口径；它既不是 close 也不是 open，无法用一句话解释。

**B 的等价实现形式**（供 DESIGN 参考）：`effective = apply_tradability(target_w.shift(1), prev_close, high, low, close, open_, ...)`，即「T−1 日信号 + T 日开盘判定」；首日目标补 0，最后一日信号自然丢弃。这样无需改动循环结构，只需把执行谓词从 `high/low` 改为 `open`。注意 `turnover` 序列随之后移 1 日（长度 T−1 不变），报告需标注 `execution_timing="t_plus_1_open"`。

### 2.6 验收锚点

1. `execution_timing` 与 `execute_at` 一致（单测）。
2. 同一目标权重下，`same_close` 与 `next_open` 的 `blocked_buy/sell` 差异与 §2.2 同向（双跑）。
3. `open_` 从「仅校验」变为「参与判定」（覆盖率检查）。
4. 首日、末日、T+1 停牌三个边界各 1 例。

## §3 D2 未知限价：`adj` 缺口的处置

### 3.1 现状与缺口规模

| 项 | 读数 |
|---|---:|
| `close` 交易日 | 1475 |
| `adj` 交易日 | 1394（缺 **81 日，5.49%**） |
| 缺口日可计算 OHLC 格 | **403,499**（占全样本 5.95%） |
| 缺口日买入触板（raw 昨收近似） | **7,477** |
| 缺口日卖出触板（raw 昨收近似） | **10,393** |
| 三大跌停日 | 2025-04-07（3,626 跌停触板）、2020-02-03（2,593）、2024-02-05（1,920） |

- 当前 `_ref_from_adj` 在缺口日返回 NaN → `judge=False` → **既不封买也不封卖**（现状是「放行」，不是「封锁」）。
- `limit_unknown` 只在「有调仓意图」时计数，无法反映「整日未判定」。

### 3.2 关键新证据：`stock_return` 在缺口日退化为原始收益（E1）

| 检验 | 结果 |
|---|---|
| 有 `adj` 日、除权格：`ref_ret = close/(1+ret/100)` vs `ref_adj` | 主板 **99.86%**、创业板+科创板 **99.91%**、北交所 **92.7%** 在 0.1% 内一致（p50=1.0） |
| 缺口日：`ret/100` vs 真实昨收收益 | **403,499 格全部一致**（max 差 5e-7，无 1 格 >1e-6） |
| 缺口日：`ref_ret/prev` | 全部 **1.0**（无任何除权信息） |

结论：`stock_return` 在有 `adj` 的除权格上以 **99.86% / 99.91%** 的精度复现 `_ref_from_adj`，可视为官方涨跌幅口径的近似（非除权格仍有约 3.7% 的差异与极端值）；但**在 `adj` 缺失的 81 日它恰好退化为原始 close 收益**，因此**不能用来填缺口**，只能作为有 `adj` 日的交叉验证。

> 附带发现：`stock_return` 为百分数（p99=10.01，max=200,400），而 [data_contract.py L662](../../backtest/data_contract.py#L662) 的 `return` 一致性检查按 decimal（[-1, 10]）判断 → 该字段若被契约消费会持续告警/误判；当前主链路未使用它，登记为数据契约待办。

### 3.3 三种处置的量化对比

| 处置 | 覆盖 | 预期判定误差 | 代价 | 评价 |
|---|---|---|---|---|
| **整日封锁**（上一轮建议 A） | 81 日 / 403,499 格 | 0 漏封，但 **100% 过度封锁** | 5.5% 交易日完全冻结；pending 堆积到下一日；turnover 出现人为尖峰 | **过度**：为了规避约 18 个买入判定翻转，冻结 40 万格 |
| **原始昨收回退 + 披露** | 同上 | 约 **18 买 / 155 卖** 判定翻转（量级估计，见下） | 零外部依赖；需 `ref_fallback_days=81` 披露 | **推荐（无 `stk_limit` 时）** |
| **拉取 `stk_limit` 覆盖 81 日** | 同上 | 0（权威） | 外部 token/积分；一次拉取 | **最优（若可用）** |

量级估计方法（E1 + 假设）：用有 `adj` 的 38,715 个除权格统计「回退 vs 正确 ref」的判定翻转率——买入 305/38,715=0.79%，卖出 2,675/38,715=6.9%；按全样本每日平均 27.8 个除权格推算，81 日约 **18 个买入翻转 / 155 个卖出翻转**。买入翻转是乐观（少封锁），卖出翻转是保守（多封锁）。这只是**判定翻转上限**，真实受影响交易更少。

补充下界（E1）：缺口日「原始收益超出板块限价」的格仅 **36 / 403,499（0.009%；19 跌 + 17 涨）**，说明缺口日的大额除权/拆股事件极少（36 格中包含 2020-02-03 的科创板异常样本）。小额现金分红无法从价格识别，但其幅度通常 1%-3%，对涨停判定的翻转概率远低于大额事件。

### 3.4 为什么回退是安全的

- 回退的错误方向可解释：现金分红使 `raw prev > ref` → 涨停价偏高（少封买，乐观）、跌停价偏高（多封卖，保守）。
- **缺口日月份分布不含 6-7 月（分红高峰）**：81 日全部落在 1-4 月与 9-12 月 → 按全样本除权密度外推的 18 买/155 卖是**上界**，实际回退风险更低。
- 缺口日包含三大跌停日；在这些日子，回退会**多封卖**（保守），不会放大跌停卖出；
- 买入侧乐观误差约 18 格/81 日，相对 403,499 格可忽略；
- 若要求零乐观，可只对「缺口日 + 回退后涨停价被触及」的格加一个 `ref_fallback_suspect` 标记，B 批做敏感性，而不是整日封锁。

### 3.5 推荐（修正上一轮 U-2）

1. **首选**：拉取 `stk_limit` 覆盖 81 日（同时获得除权/ST/北交所/低价股权威值）。
2. **无外部数据时**：`ref = prev_close` 回退；报告 `unknown_policy="fallback_raw"`、`ref_fallback_days=81`、`ref_fallback_cells=403,499`；**不要整日封锁**。
3. 保留 `limit_unknown` 计数，但语义改为「按 fallback 处理后仍无法判定」（如价格 NaN、板块 unknown），避免把缺口日误读为「已判定」。
4. B 批敏感性：`ref_policy ∈ {fallback_raw, block, stk_limit}` 三跑对照。

## §5 D4 三态：只披露、敏感性、还是改为可成交？

### 5.1 量化（E1，引擎谓词 `high >= limit - eps`）

| 板块 | 买入触及 | 一字 | 一字占比 | 卖出触及 | 跌停一字 | 占比 |
|---|---:|---:|---:|---:|---:|---:|
| 主板 | 113,530 | 6,538 | 5.76% | 41,134 | 1,664 | 4.05% |
| 创业板+科创板 | 13,214 | 267 | 2.02% | 2,243 | 106 | 4.73% |
| 北交所 | 1,193 | 185 | 15.51% | 236 | 77 | 32.6% |
| **合计** | **127,937** | **6,990** | **5.46%** | **43,613** | **1,847** | **4.24%** |

- 一字占比在主板/双创为 2%-6%，与华安证券「一字 9.2% / 换手 90.8%」（E3）同量级；北交所 15.5% 是流动性差异，不宜外推。
- 若改为「只有一字才封锁」，买入封锁从 127,937 降到 6,990（**-94.5%**），等于把 32% 的炸板日全部视为可成交——过于激进。
- 若 D1 选 `next_open`，封锁池是 17,373；三态应以 **T+1 开盘/全天** 重新定义，而不是 T 日 high/low。

### 5.2 外部锚点

| 来源 | 结论 |
|---|---|
| 腾讯云社区（提纲 S10） | 应分「未触及 / 触及打开 / 全天一字」三态，第三类保守不成交 |
| 华安证券（提纲 C-5） | 换手板 90.8% / 一字板 9.2% |
| A-1 磁吸效应（DOI 10.12012/2020-0008-16） | 越接近限价越加速趋近，但并非必然封死 |
| A-2 Cho et al. (2003) | 高频证据支持磁吸，但不等于 100% 封板 |

### 5.3 推荐

- **A（本批）**：不改成交判定；报告新增 `up_touch_cells / up_touch_one_word_cells / exec_at_limit_cells`，并把 `blocked_buy` 与 `up_touch_cells` 并列展示。
- **B（B 批收益层）**：`limit_mode ∈ {touch, exec_price, one_word}` 三跑敏感性，量化上界/下界。
- **不做 C**：一字-only 会把炸板日全部放行，与本仓「证据层保守」定位冲突；且缺少分钟数据验证。
- 与 D1 的耦合：**D1 定案后，三态问题自动降级为「执行日状态」披露**；若 D1 选 next_open，则三态应统计 `open[t+1] >= up[t+1]` 与 `h[t+1]==l[t+1]`，而不是 T 日。

## §6 D5 数据补强顺序：按「风险降低 / 成本」重排

### 6.1 候选动作矩阵

| 动作 | 覆盖问题 | 影响面（E1） | 外部依赖 | 成本 | 优先级 |
|---|---|---|---|---|---|

### 6.2 为什么顺序变了

- 上一轮按「缺口大小」排：`adj` > ST > 停牌 > 退市。
- 加入成本后：`stk_limit` 一次解决 4 类问题（限价权威源），若可得应最先；若不可得，停牌与 `adj` 回退都是**零外部依赖**的代码改动，应先做；ST 表需要外部拉取，排后；退市公告成本最高、边际收益最低。
- `adj` 从「P1 阻断」降级为「P1 可缓解」：回退 + 披露即可启用；若追求零乐观，再拉 `stk_limit`。

### 6.3 推荐落地顺序

1. **`stk_limit` 可行性确认**（是否有 token/积分；能否覆盖 2020-2026 + 81 缺口日）。
2. **停牌映射修正**（`'S'` only）+ 列缺失披露。
3. **`adj` 回退 + `ref_fallback_days` / `ref_fallback_cells` 披露**。
4. **ST `namechange` 面板**（可延后到 A 批之后）。
5. **退市公告**（仅在出现退市整理样本争议时再做）。

## §7 决策依赖关系

```
D1 执行时点 ──决定──> D4 三态的统计对象（T 日 high/low → 执行日 open/close）
     │
     └──决定──> turnover 封锁池（127,937 → 17,373 或 86,039）

     │
     └──若选 fallback──> 零外部依赖即可启用

D3 北交所 ──独立──> 必须先修，否则构建器抛错（阻断 D1/D2 的任何实测）
```

- **实施顺序建议**：D3（解阻断）→ D1（定语义）→ D2（定缺数策略）→ D5（数据补强）→ D4（敏感性）。
